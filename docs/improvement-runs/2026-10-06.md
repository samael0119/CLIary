原实现对收藏逐条查询 Catalog；任何一个保存的 ID 不再存在，就使整个列表报错。CLI `favorites`、Web 收藏页和首页收藏计数因此失败；取消收藏也先要求 Catalog 有该工具，旧收藏无法清理。此问题会在正常 Catalog 更新后直接阻断日常操作，优先于增加视觉素材或模型依赖。

本轮只处理收藏对 Catalog 变动的容错及恢复操作，不扩大到整个 Catalog 更新兼容性或重做页面。

## 改动与收益

1. Core 新增 `FavoriteEntry` / `favorite_entries()`，返回所有保存的 ID，工具元数据可为空。一次读取当前 Catalog，按精确 ID 对应，不把旧 ID 重新解析成新工具的名称或别名。收藏按保存时间倒序、同时间按 ID 排序。
2. 保留 `favorites() -> Vec<Tool>` 作为仅返回有当前元数据条目的兼容入口；CLI、Web 收藏页与首页计数改用完整入口。缺少元数据不会被当作没有收藏，实际数据库／Catalog 读取错误仍会报告。
3. 普通取消优先删除保存的原 ID，继续支持当前名称与命令别名。新增 `remove_favorite(id)` 精确删除 API，无需 Catalog 查询，重复执行不会影响复用旧 ID 为别名的另一工具。
4. CLI 显示旧 ID 与中英文恢复说明；`favorite <id> --remove --exact-id` 提供可重试的精确取消方式。普通 `--remove` 保留原有别名功能。已知条目的 JSON Tool 结构不变，缺失条目输出 `id` 与 `catalog_available: false`，不虚构名称、描述或其他元数据。
5. Web 继续使用现有页面结构和配色。缺失收藏显示 ID、原因和「取消收藏」，没有通往不存在详情的链接。新 POST `/favorites/remove` 把 ID 放在表单正文中，校验 CSRF，精确取消后回到收藏页；长 ID、中文、引号、斜杠等不会形成错误路径或 HTML 注入。
6. 不迁移数据，不删除备注或使用历史。如果相同 ID 重新进入 Catalog，保存的收藏自动重新显示资料。README 说明 JSON 和 API 边界及取消命令。
