# M2：历史导入 → 年报洞察 → 展示与导出

用户在 2026-10-08 授权按此顺序实现。复用现有 Core、SQLite 与桌面 Web 视觉体系，不自动读取用户历史，不把 mock 写入真实数据。

三个需求采用依赖分支：history-import → wrapped-insights → wrapped-presentation。后面的分支包含前面的提交，便于顺序 review；本轮不直接修改 main。

## 1. 历史导入

分支：`feature/2026-10-08-history-import`。

- Bash 时间戳、Zsh extended／metafied、Fish YAML-like 历史；显式选择文件，默认预览，`--apply` 才写入。
- 保存可验证时间、程序名与来源，不保存命令参数、完整命令或路径。
- 无日期观察单独保存，可通过 `history --undated` 查看；不虚构日期，不进入时间统计。
- 重复文件与实时采集重叠去重，同时保留单份快照内同秒重复的次数。缺少参数意味着跨快照同秒事件可能无法区分，明确限制。
- 复杂命令保守跳过，文件上限 32 MiB；数据库 v1→v2 事务升级，保留收藏、备注与事件。
- 验证：全 workspace 45 项测试通过（含新增 5 项解析／预览隐私／重复导入／无日期／实时重叠／迁移场景）。

## 2. 年报洞察

分支：`feature/2026-10-08-wrapped-insights`。

范围：首次记录于本年的工具、年度新宠、分类、已收藏但低频／无记录的工具、前一年同时间段记录变化、逐工具变化及来源口径。只报告数据支持的观察，不声称安装日期、完整调用数或工具替代关系。

## 3. 展示与导出

分支：`feature/2026-10-08-wrapped-presentation`。

范围：保留已有桌面 UI，给年报添加上述事实、可追溯链接、清楚的数据来源与缺失状态。CLI／Web 共享数据，支持独立静态 HTML／JSON 导出，无脚本、外部资源或联网依赖；测试演示数据仅在临时目录。

本地模型摘要、语义搜索、Logo、多级分类不属于本轮；完成这三步后再排期。既有扫描子进程超时问题和旧页面样式提醒仍由独立修复处理。
