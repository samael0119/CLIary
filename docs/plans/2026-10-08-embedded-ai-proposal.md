## 1. 产品目标

用户在 CLIary 内启用本地智能，完成模型准备和日常使用，无需自行部署推理服务、填写服务地址或安装 Python 环境。完成模型下载后，推理和检索可离线运行。

AI 遵守 PRD 第 47 节：用于理解、检索、排序和总结；Catalog 与 Core 的统计结果提供事实。功能按实际收益逐步交付。

| 场景 | 用户体验 | 交付次序 |
| --- | --- | --- |
| 自然语言／跨语言搜索 | 输入“找一个能交互查看磁盘占用的工具”或英文描述，找到 Catalog 内相关工具 | 首期 |
| 条件检索 | 输入“本机装过、能处理 JSON 的工具”，识别明确条件并由 Core 过滤；不确定的条件向用户说明 | 首期后续增强 |
| 工具比较摘要 | 比较页面点击“总结差异”，展示有资料依据的差异与缺失信息 | 第二期 |
| 年报解读 | 年报点击“解读这一年”，从聚合统计解释变化，并关联到实际指标 | 第二期 |
| 相似工具 | 使用语义相似性补充 Catalog 人工关联，保留相似依据 | 后续按收益决定 |

首期范围仍对应本轮授权的智能搜索；比较、年报生成不自动扩大为本轮必做项。

## 2. 在现有产品中的入口

### 本地智能设置

提供“本地智能”入口，首次使用显示功能说明、准确下载体积、建议资源与“下载并启用”。允许导入兼容的已有模型文件。

模型状态明确分为：未准备、下载中、校验中、准备索引、就绪、运行失败。支持下载进度、取消／续传、失败重试、关闭和删除模型。

默认关闭，安装或首次运行只提示可选能力。普通搜索、工具浏览及年报均可独立使用。

### 搜索

启用后，在“发现工具”搜索框中选择智能搜索。支持真实任务描述和跨语言表达，结果仍使用现有工具卡片，链接到 Catalog 详情。明确标注语义相关结果；直接输入工具名时准确匹配优先。

首期不生成未经验证的推荐理由，不将向量相似度显示为正确率。超时、索引失效或模型异常时展示普通搜索结果和可操作的恢复提示。

后续条件检索必须展示识别出的过滤条件。例如“已安装”来自 Installed 数据，“Linux”来自 Catalog 平台字段；模糊的“最好”“更快”不能凭空变成事实过滤。

### 比较和年报（后续）

比较页保留原有资料表格；年报保留原有真实统计。用户主动点击才生成摘要。摘要关联到具体工具字段或统计指标，缺失资料明确说明。

## 3. 推荐技术路线

### 引擎随产品交付，模型由产品管理

使用 llama.cpp 作为本地推理引擎，锁定经过验证的源码版本。随 CLIary 安装包交付受管理的推理子进程，调用本地库；用户不需要单独安装或维护推理服务。

推荐以管道传递受限请求／响应，不向局域网开放监听。独立进程隔离模型崩溃，可实施硬超时、取消、资源限制与退出清理。Web 和 CLI 统一通过 Core 使用它。

CPU 是首期可用基线，GPU 加速根据平台能力和验证结果启用，不以 GPU 作为必需条件。锁定引擎与模型兼容版本，避免依赖上游 latest。

### 检索模型与生成模型分开

- 首期候选：Qwen3-Embedding-0.6B，用于语义／跨语言检索。它是嵌入模型，不能承担文字摘要。
- 第二期候选：Qwen3-1.7B 的 GGUF 版本，用于条件理解和短摘要。先在真实样例上验证，效果不足再评估更大模型。
- 用户启用哪种能力，才下载相应模型；不要求同时准备两套权重。
- 最终量化版本、来源、下载字节数、SHA-256、许可证、兼容引擎版本写入固定清单。公开候选不等于已经通过本机性能与质量验证。
- 文件体积与实际内存占用分别显示；不使用模型参数量推断内存需求。先测 CPU 冷启动、预热查询、峰值内存与多语言质量，再确定默认配置。

### 数据流程

Catalog 描述／标签 → 文档嵌入 → 本地缓存索引。

用户查询 → 查询嵌入 → 语义排序与准确名称优先规则 → Core 构造真实工具结果 → CLI／Web。

第二期：Core 提供有限的比较字段／聚合统计 → 模型生成受约束输出 → 字段及引用校验 → 页面展示摘要。

当前目录规模小，采用本地向量缓存与线性比较即可，不引入独立向量数据库或额外 Reranker。索引以模型内容哈希、Catalog 内容哈希和输入格式版本标识；更新后重建，失败保留旧缓存并正确标记不可用。索引不保存搜索词、历史或备注。

## 4. 可靠性与隐私

- 下载只在用户触发时发生；验证 HTTPS 来源、固定模型清单与校验和。下载到临时文件，成功后原子替换；中断不损坏可用模型。
- 模型按需加载，空闲释放。避免每次短 CLI 查询都长期残留后台进程；Web 可在限定空闲时间内复用。
- 限制输入长度、上下文、线程、并行请求和运行时间。支持取消，崩溃可恢复。
- 首期模型输入仅有 Catalog 内容和查询。生成年报摘要时只提供聚合统计；不自动读取完整历史、参数、备注或个人文件。
- 模型不执行命令，不生成安装命令／版本／许可证等工具事实。生成内容明确标注且可核对出处。
- 关闭 AI 或模型不可用时，基础功能不调用推理、不阻塞、不要求补装模型。
- CLI 与 Web 共用 Core 逻辑，兼容现有配置和数据库；普通 search 的输出保持兼容，新增 AI 模式独立标注状态。

## 5. 实施步骤与验收

每个阶段独立分支，按依赖顺序 review。

### A：内置运行时与模型准备

实现受管理引擎、固定模型清单、下载／导入／校验、状态与清理，提供 CLI 与 Web 可操作入口。

验收：首次启用、取消下载、断点续传、坏文件拒绝、无网络导入、进程退出／崩溃清理；用户无需部署服务。

### B：智能搜索完整闭环（首期交付）

构建 Catalog 索引，实现跨语言任务检索、准确工具名优先、普通搜索回退和页面状态。

验收：至少 30 个预先标注的中英文任务样例，覆盖磁盘、文件、文本、JSON、Git、网络、容器等目录真实内容；比较普通搜索与智能搜索的 Top-3 命中，不用 mock 宣称真实收益。目标是语义任务检索有明确提升，准确名称查询不退化。记录冷／热查询耗时和峰值内存，不预先承诺未经测量的秒数。

用 mock 验证异常和边界，用真实候选模型验证检索质量；断开网络后仍能使用已下载模型。检查明暗主题、中英文、键盘操作、加载／取消／回退状态。

### C：验证与安装包发布

完成 workspace 测试、Clippy、格式、Catalog 校验及实际安装包测试。推理引擎加入原有 Linux／macOS 发布矩阵，各平台分别验证；未验证平台不能宣称可用。

2026-10-08 再次尝试触发 GitHub Actions，返回 HTTP 422：Actions has been disabled for this user；仓库 permissions.enabled=true。这是 GitHub 管控的账号限制，恢复需要 GitHub Support 复核。源码改动无法解除它。远端 CI 恢复前可完成本地验证与本机平台的包准备；跨平台验证和完整发布仍需记录该阻碍。

### D：生成能力（另行排期）

在 A 的运行时上增加生成模型；先选比较摘要或年报解读一个完整场景，验证出处、数字、资料缺失及模型幻觉处理。自然语言过滤可沿此能力增强。避免首期同时承担聊天、摘要、复杂查询和 Agent 执行。
