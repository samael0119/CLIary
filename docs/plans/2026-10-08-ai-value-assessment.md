# CLIary 接入本地模型的收益复评

日期：2026-10-08。结论：当前暂缓完整内置大模型；保留语义检索作为需要验证收益的候选。GitHub Actions 按用户要求不纳入本次评估。

## 依据与边界

检查当前 main 的搜索实现，并用现有二进制在隔离临时工作区运行 13 个搜索样例。未读取或导入用户真实历史，未安装模型，未修改产品代码。

Catalog 共 55 个工具，55 个有描述，4 个有非空 keywords，8 个有非空 features，5 个有非空 common_commands。这些数量只衡量字段是否填写，不证明内容质量。目录数据完整性尚有明显提升空间。

当前搜索使用 FTS、文本包含和中文双字片段计分，未对自然语言任务进行语义理解。

| 输入 | 实际前三项 |
| --- | --- |
| ncdu | ncdu |
| 磁盘空间 | dua、dust、gdu |
| 想知道电脑里哪个文件夹占地方 | ag、bat、cat |
| 查找文件 | fd、find、ag |
| 忘了文件名，只记得一小部分 | ag、bat、cat |
| 处理 JSON | jq、ffmpeg、yq |
| 把 JSON 排版成容易看的样子 | jq、bottom、btop |
| 查看 Git 提交历史 | delta、gh、git |
| 看一下仓库过去的提交 | 无结果 |
| disk usage | du、dua、dust |
| find files by name | find、ag、fd |
| make JSON readable | jq |
| inspect git commits | delta、gh、git |

这些样例说明普通搜索存在排序和表达覆盖问题；这是探索性抽查，不是完整基准，也没有模型对照，不能宣称模型已经提高了命中率。

## 分场景判断

| 场景 | 当前增量收益判断 | 原因与替代方式 |
| --- | --- | --- |
| 忘记工具名、描述任务寻找工具 | 中，有验证价值 | 真实搜索缺口；先补同义词／任务关键词并调整排序，评估仍无法覆盖的表达 |
| 中英文跨语言检索 | 中 | 已有中英文描述；其他语言和复杂转述可能从嵌入模型获益，需实际样例证明 |
| 已安装、分类、平台等条件 | 低 | 现有结构化字段可直接筛选；明确条件无需生成模型 |
| 比较摘要 | 当前低 | 许多工具比较字段尚未填写，模型不能补出可靠事实；先完善比较资料与可核对的差异展示 |
| 年报文字解读 | 当前低 | 已有 Core 洞察；规则模板能解释指标，模型主要增加措辞变化；历史不足和无时间戳问题无法靠模型修复 |
| 目录外工具推荐／安装识别 | 不作为模型收益 | 当前产品以 Catalog 为事实来源；语义模型不扩大真实目录，也不能代替安装检测 |

## 成本与产品契合度

收益主要集中于搜索转述，但完整内置方案引入下载／续传／校验、模型生命周期、进程管理、索引失效、异常回退、跨平台构建以及质量评估等长期成本。关闭 AI 时仍要保留完整基础路径，需要同时维护两种行为。

用户还需承担模型文件、运行内存、CPU 占用和首次加载等待。官方 Qwen3-1.7B-GGUF 当前 Q8_0 权重为 1.83 GB；这是生成候选的文件大小，不代表所有模型的体积或实际内存。具体候选的速度和内存尚未实测。

CLIary 的日常价值是快速找到工具、核对真实资料、了解本机环境与记录。当前证据不足以证明完整模型系统的投入与这部分增量收益相称。

## 建议顺序

1. 先选日常搜索表达，建立与实现无关的预期相关工具集合，并覆盖准确名称、短词、自然语言与中英文。
2. 补工具用途、任务同义词、关键词和比较特性；改进词权重、中文处理及相关性排序。资料同时服务搜索、详情与比较，且无需模型。
3. 在上述基线上，用至少 30～50 个未针对单一实现调优的查询比较普通搜索与小型嵌入模型。只做隔离验证，不先建设完整模型下载／管理 UI。
4. 决定是否集成时看 Top-3 命中提升、准确名称不退化、真实使用频率、冷／热延迟、资源占用和启用成本。收益阈值事先约定，不能测完才选择有利指标；当前不编造 ROI、命中提升或响应时间。
5. 若语义检索有稳定、实用的优势，再交付一个可选搜索能力。生成摘要按独立问题重新评估，不随检索一起自动纳入。

### 再次评估的触发条件

实际使用中持续出现转述搜索失败；目录和用途明显扩充；用户经常提出组合查询，且常规筛选难以支持。目录规模只是参考，不以达到某个工具数量自动触发模型接入。

## 对前一版方案的修正

`2026-10-08-embedded-ai-proposal.md` 保留为未来技术参考，当前状态改为暂缓。此前从可实现性直接规划内置模型管理，收益论证不足。本次建议先投资目录质量与搜索可靠性，再用对照验证决定是否值得接入。
