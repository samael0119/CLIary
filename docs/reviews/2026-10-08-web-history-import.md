# Web 历史预览与导入（2026-10-08）

## 范围与收益

用户要求 Web 提供实际预览／导入按钮。本轮将此前仅供复制的导入命令补为完整操作流程，继承桌面绿色工作台，保留中英和明暗主题。

- 分支：`codex/2026-10-08-web-history-import`，基于安装／首次运行引导提交 `7f92e97`；本分支包含此前 M2 与别名功能的依赖。提交用 `git log -1 codex/2026-10-08-web-history-import` 查询。
- 「使用历史」顶部与已有历史区域提供导入入口；在线年报的数据范围区域也可进入。安装／CLI 的引导详见前一阶段记录。
- 检测文件仅检查位置和 metadata，选择并点击预览才读取内容。支持 Bash、Zsh、Fish，手动路径（含 `~/`）和可选别名快照；别名仍需从日常 Shell 导出，不加载用户配置。
- 预览清楚区分新增有日期记录、无日期观察、已有记录、跳过条目、已有记录重新归类，显示可靠日期、最多20个程序名和别名归属。
- 确认后显示实际保存结果并链接使用历史／年报。没有新增时禁用导入，读取错误保留可编辑表单；过期／已用／重启丢失的预览提供重新预览入口。

## 实现与可靠性

新增三个路由：`GET /history/import`、`POST /history/import/preview`、`POST /history/import/apply`。两项 POST 校验现有 CSRF，保留仅 loopback 监听与 Host 检查。导入页面返回 `Cache-Control: no-store`。

复用 Core 的 `HistoryImportPlan`，仅持有程序／时间／数量／别名事实，不持有完整命令参数。预览以随机256位令牌在服务器内存暂存10分钟，最多4份；满额淘汰最旧预览，重启清空。应用使用同一份解析快照，不重读变化后的文件，并在数据库事务中重新检查重复；成功后消费令牌，重复点击不会再次应用。失败保留可重试计划。

文件解析与应用放入 blocking worker，避免同步解析占用 async runtime。页面提交显示处理中并禁用按钮，浏览器返回恢复操作。Web 成功导入标记历史引导已完成，未来 Shell 采集仍是独立配置。

## 使用与边界

在当前工作区运行 `./target/debug/cliary web`，访问 `http://127.0.0.1:8848/history/import`，或「使用历史 → 导入旧历史 → 预览这份文件 → 确认导入」。旧用户可用 `./target/debug/cliary setup history` 重开 CLI 引导。

此版本保持本地分支供试用，未推送／合并 main。预览不上传文件；本地路径属于运行 CLIary 的这台电脑。历史设置可能遗漏／合并命令，无日期观察不进入年报，当前别名快照不能证明过去配置完全相同。

用户追加询问 Agent 调用记录：目前导入与采集来源仍为 Shell。交互终端启动 `codex` 等程序可记录启动；Agent 内部独立非交互进程的工具调用通常没有 Shell 历史，尚无专门的 Agent 日志导入。后续可独立评估显式选择 Agent 执行日志／事件来源，区分终端操作与 Agent 调用并避免重复统计，本轮没有实现或宣称该覆盖。
