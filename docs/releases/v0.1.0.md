# CLIary v0.1.0

首个正式版本，2026-10-09（Asia/Shanghai）。本地工具目录、使用记录与 Web 工作台共用 SQLite 数据，无需账户或大模型服务。

## 主要功能

- 55 个内置工具，中英文任务关键词和标签搜索；工具速查、特性比较、收藏和备注。
- 扫描 PATH、常见语言开发环境和包来源；已安装工具可按名称、目录、来源和分类筛选。
- Bash／Zsh／Fish 使用采集，以及旧历史的显式预览和导入；支持用别名快照将 `gst` 等名称归到实际工具。
- 使用历史、统计、年度报告与离线 HTML／JSON 导出。无日期历史单独保存，不猜测年份；不存储原始命令参数。
- 桌面 Web 页面、中英文与明暗主题；全局搜索支持 Ctrl/Cmd+K、非编辑区域的 `/` 和点击入口。
- 首次运行提供扫描、未来历史采集和旧历史导入指引；私有 Release 和离线安装支持校验和及原子升级。

SQLite、Catalog 与 Web 静态资源内置，无需安装 Rust 或 SQLite。可选扫描和 Shell 集成使用的系统工具仍由操作系统提供。

本次提供 Linux x86_64 和 ARM64 预编译包；ARM64 经 QEMU 验证，尚未进行实机验收。macOS 暂以源码构建使用，后续经对应环境验收再提供安装包。源码构建和静态构建步骤见 README。

其他资产：`install.sh`、`SHA256SUMS`、`BUILDINFO.json`、`manifest.json`、`catalog.db.zst`。Catalog 版本为2，内容与随程序内置的55个工具一致；更新 Catalog 不修改个人使用数据库。BUILDINFO 记录源码提交、构建工具链、链接方式、文件大小和二进制 SHA-256。

## 安装与试用

仓库保持私有，需已登录且有仓库访问权限的 GitHub CLI：

```sh
gh auth login
cliary_installer_dir="$(mktemp -d)"
gh release download v0.1.0 --repo samael0119/CLIary \
  --pattern install.sh --dir "$cliary_installer_dir"
sh "$cliary_installer_dir/install.sh" --github --tag v0.1.0
```

默认安装到 `~/.local/bin/cliary`，按提示选择是否扫描和采集未来历史。旧历史须先预览再确认导入。确保安装目录已在 PATH 中，然后：

```sh
cliary --version
cliary --lang zh-CN search 磁盘空间
cliary show ncdu
cliary compare ncdu dust
cliary web
```

Web 地址为 `http://127.0.0.1:8848`。升级后需重启运行中的 Web 服务以加载新二进制；收藏、备注与历史保留。Linux 安装器从同一次 Release 的 SHA256SUMS 选择包，优先 musl，缺少 musl 条目时兼容旧 GNU 包；GNU 包仍受其自身 glibc 要求约束。

离线时，下载同一版本的安装包、`SHA256SUMS` 和 `install.sh` 到同一目录，执行 `sh install.sh --from DIRECTORY`。非交互安装可追加 `--no-scan --no-history`。

## 验证与边界

- 当前源码73个 Rust 测试通过；55条 Catalog 的结构与引用校验通过。
- Linux x86_64 发布静态二进制通过8项安装测试，包括私有固定版本下载参数、旧 GNU 包兼容、校验失败保护及升级数据保留。
- 两种 Linux ELF 均无 PT_INTERP、无 DT_NEEDED；x86_64 在 Ubuntu 20.04 和 Alpine 3.20.3 的只读、无网络容器中版本、搜索和详情均通过。容器验收覆盖用户态环境，共享宿主内核。
- x86_64 实际静态安装包通过隔离环境的离线安装、升级、Catalog 同步、年度 HTML 导出和 Web 页面检查。
- ARM64 实际静态二进制经 QEMU 8.2 执行，搜索、比较、收藏备注、人工历史导入、Catalog 同步、年度 HTML 导出和 Web 路由通过；没有将仿真结果标为实机验收。
- 使用记录代表保留的采集／导入观察，不能保证完整执行历史。数据库使用 schema v2，旧程序不能打开升级后的数据库。

本次手动构建和发布，GitHub Actions 配置保持原状。
